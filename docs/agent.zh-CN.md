# 内置 agent

[English](agent.md) · **简体中文**

`ocu run` 自己完成一个目标，规划模型（planner）可以是任意兼容 OpenAI 接口的对话模型。
在 MCP 下，同一个 agent 就是 `run_task` 工具。

## 运行

```sh
export DEEPSEEK_API_KEY=...
ocu run "新建一条备忘录写 hello"
ocu run "用计算器算 37 乘以 12，把结果告诉我" --no-cache
```

每一步执行时都会打日志。最后 ocu 会打印结果、规划模型的调用次数，以及时间花在了哪里：

    done in 3.9s, 2 planner calls (observe 1150 + model 1800 + wait 600 + actions 400 ms)

达成目标时退出码是 0，否则是 1。一次运行最多 25 轮规划。`--no-cache` 表示这次运行跳过[动作缓存](#动作缓存)。

## 模型

每一轮，agent 读取屏幕，向规划模型要接下来的步骤。可选的模型可以省时间：

| 模型 | 是否必需 | 设置方式 | 作用 |
| --- | --- | --- | --- |
| 规划模型 | 是 | `DEEPSEEK_API_KEY`，或 `OCU_BASE_URL` + `OCU_API_KEY` + `OCU_MODEL` | 每轮规划一批步骤。默认是 DeepSeek `deepseek-chat` |
| Jev 完成判断 | 否 | `TYPESAFE_API_KEY` | 从第二轮开始和规划模型同时运行，判断目标是不是已经达成。它有至少 90% 的把握、而规划模型还想继续时，会带着这个提示再问规划模型一次 |
| Jev 按键模式 | 否 | `TYPESAFE_API_KEY` + `OCU_JEV_PRESS=1` | Jev 挑出接下来的一到两次按下。如果规划模型 400 ms 内没回答，就用 Jev 的 |
| 快速模型 | 否 | `OCU_FAST_MODEL`，或 `OCU_FAST_URL` | 一个很快的模型，给出一步。没把握或太慢时交回规划模型 |
| 视觉模型 | 否 | `STEPFUN_API_KEY`，或 `OCU_VISION_*` | 用于[截图兜底](#截图兜底) |

Jev 是 [TypeSafe](https://typesafe.ai) 的分类模型。规划模型回答之后，完成判断最多只再等 300 ms，
所以慢的判断不会给每一轮都多加几秒。所有变量和默认值见[配置](configuration.zh-CN.md)。

每次和规划模型来回一趟大约要一秒，所以 agent 的设计目标就是尽量少来回。
在 0.6.0 的基准测试里，模型仍然占了一半以上的时间。

## 批量与本地完成检查

规划模型每一轮发来一批步骤。

**屏幕变化之后能接什么。** 在会改变屏幕的步骤之后，批量会等屏幕稳定，然后继续执行两类步骤：

- 不需要 ref 的步骤：按键、往聚焦的输入框里打字、菜单、打开应用或 URL、`find_text`；
- 在一次小变化之后，元素仍然在、而且没变的步骤（全选，然后加粗）。

其他步骤都会结束这一批，由规划模型看新屏幕。

**不再调用模型就结束。** 一批步骤可以以 `done` 加 `expect` 结尾：`expect` 是一段只有目标达成后才会出现的文字，
比如新窗口的标题、计算器的结果，或者打进去的文字的开头。agent 在本地检查它，
不再问规划模型就结束。这个检查很严格：

- 这段文字必须出现在窗口标题里，或者出现在这批步骤之前屏幕上没有的内容里。控件和单行输入框不算。
- 数字和单词按完整的词匹配：`444` 不算出现在 `4,440` 里。
- 这批步骤自己打的文字，只有在打字是最后一步、并且某个文本区现在恰好就是这段文字时才算。
  重复这段文字的错误提示不算证据。
- 最后弹出了窗口或对话框的话，这一轮交回规划模型。
- 对于提问类的目标，期望的文字必须是总结里的答案，而不是目标里的原话。
- 总结里不能出现既不在目标里、也不在屏幕上、也不在之前读到的内容里的数字或引号里的名字。

拿不准时，由规划模型来看。没有 `expect` 的 `done` 需要先看一眼屏幕。

## 防护

- 在没变化的屏幕上不会重复同一个操作。会告诉规划模型这个操作没起作用，让它换个办法。
- 规划模型在两个操作之间来回切换时会被叫停，并让它用 `note` 记下需要的信息再继续。
- 总结只覆盖了目标的一部分、或者声称了屏幕上没有的东西的 `done`，不会被接受。

规划模型还有两个不在[操作列表](concepts.zh-CN.md#操作)里的操作：`note {text}` 记下一条之后几轮要用的信息
（比如切换应用之前），`done {summary, expect?}` 结束运行。

## 截图兜底

辅助功能树里缺元素时（画布类应用、游戏、部分 Electron 应用），规划模型还可以用两个操作：

- `click_visual {target}`：给窗口截图，用 GUI 定位模型找到描述的元素并点击。之后会把你的光标放回原处。
- `read_visual {question}`：就这个窗口向视觉模型提问。答案会进入历史，供下一轮使用。

两者都需要视觉模型的 key 和屏幕录制权限。默认用 StepFun `step-gui` 做定位
（在计算器按钮上误差 0–2 pt），用 `step-1o-turbo-vision` 做阅读。其他选择见[视觉模型](configuration.zh-CN.md#视觉模型)。

## 动作缓存

一次成功的运行会以“目标模式 → 步骤”的形式存进 `~/.cache/ocu/actions.json`，
以开始时最前面的应用作为键的一部分。下次运行匹配的目标时，会先重放这些步骤。

- **参数。** 目标里引号中的文字和数字会变成参数，所以 `算 37 乘以 12` 的记录可以用于 `算 906 乘以 7`。
  在数字键上按出某个参数的那几下，会按新值重新按一遍。
- **按角色和标签记录元素。** 步骤里存的是元素的角色和标签，而不是 ref，重放时再匹配到新的 ref。
- **重放后检查。** 重放之后规划模型会看一次屏幕。只要它需要修正任何东西，这条记录就会被删掉，下次运行重新记录。
- **不用模型的重放。** 如果一次运行以 `done` + `expect` 结束，而且期望的文字就是目标自己的文字
  （一个参数，比如备忘录的内容或一个名字），这条记录会保留这个 expect。
  重放后这段文字出现在屏幕上，就不调用任何模型直接结束。
  从旧屏幕上读出来的结果、数量或标题永远不会被重放，由规划模型来检查。
- **不缓存的情况。** 读取内容的运行（`find_text`、`read_visual`、`note`），因为结果会变。

`ocu cache` 列出所有记录及其命中次数；`ocu cache clear` 删除它们。`OCU_CACHE=0` 关闭缓存，
`OCU_CACHE_FILE` 改变它的位置。基准测试默认关闭缓存，除非设置 `OCU_CACHE=1`。
